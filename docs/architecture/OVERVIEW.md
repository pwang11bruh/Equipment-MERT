# Architecture Overview

## Stack
| Layer | Choice |
| --- | --- |
| Framework | Next.js 15 (App Router, React 19, Server Actions, Turbopack) |
| UI | Tailwind CSS v4, shadcn/ui (style `radix-nova`, icons `lucide-react`), `sonner` toasts |
| Forms / validation | `react-hook-form`, `zod` (v4) |
| Charts | `recharts` |
| Dates | `date-fns` |
| Database / Auth | Supabase (Postgres 17, Auth, RLS), `@supabase/ssr`, `@supabase/supabase-js` |
| Email / SMS | Resend (`resend`), Twilio (`twilio`) |
| Hosting | Vercel (app and cron) plus Supabase Cloud |
| Runtime | Node 22 LTS (Homebrew `node@22` is keg-only: `export PATH="/opt/homebrew/opt/node@22/bin:$PATH"`) |

## Request flows

### Member submission
```
Phone → /submit (no cookie) → PIN form → server action verifyPin
      → service client rpc('verify_member_pin', {p_pin, p_client_hash})
      → ok → startMemberSession() sets signed cookie → form renders
Form submit → server action submitUsage → hasMemberSession() ✔ → zod ✔
      → service client rpc('process_submission', …)  [FEFO issue from equipment_room]
      → _refresh_alerts() inside the same transaction
      → (Phase 4) after(): dispatch any new critical alerts
      → confirmation screen (shows shortfall if status = 'flagged')
```
The member form needs the item list. The server reads `items` (id, name, category, unit) with the service client and **never sends quantities** to members.

### Admin
```
/admin/* → middleware: Supabase session? else → /admin/login
        → (protected)/layout: isAdminRequest() (rpc is_admin) else sign out + error
Reads:  server client → views (v_item_stock, v_lots, v_next_backstock_batch, v_fefo_violations, v_monthly_item_usage), alerts, submissions…  (RLS: is_admin())
Writes: server client → rpc('admin_receive_stock' | 'admin_transfer_lot' | … )
        catalog/recipients/settings → direct table writes (RLS allows admin)
```

### Daily cron (Phase 4)
```
Vercel Cron → GET /api/cron/daily (Authorization: Bearer CRON_SECRET)
  → service rpc('refresh_alerts')
  → select open alerts where last_notified_severity is null or < severity
  → per recipient (routed by alerts.audience): digest email (warning+), SMS (>= sms_min_severity)
  → update alerts.last_notified_* ; insert notification_log rows
```

## Conventions
- **Server-first.** Use Server Components and Server Actions. Use `"use client"` only for interactive widgets.
- **No inventory math in TypeScript.** Quantity changes always go through SQL RPCs (see BUSINESS_LOGIC.md).
- **Validate twice.** Use zod in the action for UX, and let SQL checks and constraints enforce the real rules.
- **Member item picker = flat A–Z list + search** (ADR-010). There are no category headers on the member form; categories are used only in the admin and analytics views.
- **Alphabetical ordering (owner request).** Every list of categories or items, on the member form, admin tables, exports and alert digests, is sorted A–Z, case-insensitive: category name first, then item name. Sort by name rather than `item_categories.sort_order`, so new categories added later stay in order automatically.
- **Mobile first.** Use the member form at 360px width as the baseline, with tap targets ≥ 44px.
- **Imports** use the `@/` alias, which maps to `src/`.
